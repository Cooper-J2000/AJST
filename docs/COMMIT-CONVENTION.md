# AJST 提交约定（P2-2）

> 目的：让 66 条历史那种「前缀五花八门、14 条连冒号都没有」的情况不再扩散，
> 并且让"部署的是哪个版本"这件事第一次变得可指认。本文件是**约定**，
> 不是历史判决——已有提交不追改。

## 1. 主题行格式

```
<范围>: <中文简述>（vX.YZ）
```

例（取自真实历史）：

```
core: tag 索引表 + T0 元数据 + lightcurves MJD 权威时间列（v2.23）
ui: 分页窗口跟随虚拟化 / 对比图 clip / 图例对齐（v2.25）
scripts: 新增 preflight 预检（8 组护栏，对应已踩过的坑）
```

- 范围必须来自下面那张表；**跨两个域**时选主要影响面，其余在正文说，不要写 `ui+api`
  这种复合前缀（历史上出现过，之后不再新增）。
- 版本号 `（vX.YZ）` 放在主题行末尾：只有"成批功能冻结、准备部署"的那一条提交带版本号，
  改动随该批走。纯文档/脚本提交可以不带。
- 正文（可选）：动机、影响面、验收方式。多行用 `-m` 多次或 heredoc。

## 3. 可选 trailer（多 agent 场景建议带）

```text
core: lightcurves MJD 权威时间列（v2.23）

动机：time 是画图缓存列，mjd 才是权威时间，写入必须联动。

Verified: scripts/acceptance/run_all.sh → 236 passed
Agent: hermes
```

- `Agent: hermes | kimi-code | opencode` —— 谁改的。多 agent 并行时这是唯一的归因线索。
- `Verified:` —— 改完实际跑过的命令与结果。写**真实输出**，不写"应该没问题"。
- **trailer 块的硬性规则（2026-10-08 实测补正）**：
  1. `token` 与分隔冒号都必须是 **ASCII**：`Verified:` ✅；`验收：` ❌、`Verified：`（全角冒号）❌。
     这类行会让**整块 trailer 被 git 静默忽略**——不是"时灵时不灵"，是整块失效。历史提交
     `05d218a` / `8363aef` 的 trailer 就因此没被 `%(trailers)` 读出；`d64794f` 的
     `Agent: kimi-code` 因单独成段而正常。
  2. trailer 块必须是**最后一个段落**，块前**空一行**，且**块内每一行都得是 trailer**：
     正文（如 `动机：…`）若与 trailer 同段，会把整块带塌；正文请用空行与 trailer 段隔开。
  3. 续行（行首带空白）会并入上一条 trailer；同一条 trailer 的多行不要用空行分隔。
- 核对：`git log -1 --format='%(trailers)'` 有输出即认；或 `git interpret-trailers --parse < 消息`。

**放置口径（v2.31 起）**：tag 打在**批次末提交**。v2.28/v2.29 的教训是，标记提交常常
是批次中间的后端提交，tag 打在那里会让 `git checkout vX.YZ` 拿不到同批的前端/验收/文档；
tag 的语义是「checkout 它就得到这一版的完整仓库状态」。

```bash
git tag -a vX.YZ <commit> -m "vX.YZ (YYYY-MM-DD): <主题>"
git push origin vX.YZ
# 移动尚未被他人拉取的 tag（远端需强推）
git tag -f -a vX.YZ <commit> -m "..."
git push --force origin vX.YZ
```

**与版本历史的关系**：`docs/TECHNICAL.md` §十一 每个版本应有对应条目；v2.28 / v2.29 的
条目 2026-10-02 补记（发布当时漏写），v2.31 条目随本版写入。
