# AJST 提交约定（P2-2）

> 目的：让 66 条历史那种「前缀五花八门、14 条连冒号都没有」的情况不再扩散，
> 并且让"部署的是哪个版本"这件事第一次变得可指认。本文件是**约定**，
> 不是历史判决——已有提交不追改。

## 1. 主题行格式

```
<范围>: <中文简述>（vX.YZ）
```

例（取自真实历史）：

```
core: tag 索引表 + T0 元数据 + lightcurves MJD 权威时间列（v2.23）
ui: 分页窗口跟随虚拟化 / 对比图 clip / 图例对齐（v2.25）
scripts: 新增 preflight 预检（8 组护栏，对应已踩过的坑）
```

- 范围必须来自下面那张表；**跨两个域**时选主要影响面，其余在正文说，不要写 `ui+api`
  这种复合前缀（历史上出现过，之后不再新增）。
- 版本号 `（vX.YZ）` 放在主题行末尾：只有"成批功能冻结、准备部署"的那一条提交带版本号，
  改动随该批走。纯文档/脚本提交可以不带。
- 正文（可选）：动机、影响面、验收方式。多行用 `-m` 多次或 heredoc。

## 2. 范围表（13 个，按子系统而非按文件路径分）

| 范围 | 覆盖 |
|---|---|
| `core` | 数据模型/迁移/时间与坐标基准、认证与配置 |
| `api` | 后端接口与序列化（routes/ 的行为） |
| `ui` | 前端交互、页面、图表 |
| `data` | 数据入库、回填、清洗、口径修订 |
| `etl` | 批量抽取脚本与管线（GCN 抓取、导入器） |
| `sedfit` | SED 拟合 M1–M5（builder/模型/闭包/玻尔兹曼） |
| `hostfit` | 宿主拟合与宿主统计 |
| `fitting` | 光变时变函数拟合 |
| `spectra` | 光谱（上传、抠图、消光改正、下载） |
| `filters` | 滤光片定义与透过率曲线 |
| `extinction` | 银河/宿主消光改正（CSFD + P92） |
| `scripts` | 运维与验收脚本（preflight、bootstrap、acceptance） |
| `docs` | 文档、口径说明、AGENTS.md |

## 3. 可选 trailer（多 agent 场景建议带）

```
core: lightcurves MJD 权威时间列（v2.23）

动机：time 是画图缓存列，mjd 才是权威时间，写入必须联动。
验收：scripts/acceptance/run_all.sh → 236 passed
Agent: hermes
```

- `Agent: hermes | kimi-code | opencode` —— 谁改的。多 agent 并行时这是唯一的归因线索。
- `验收:` / `Verified:` —— 改完实际跑过的命令与结果。写**真实输出**，不写"应该没问题"。

## 4. 检查在哪

`scripts/preflight.sh` 第 9 组会看**未推送的提交**：缺版本标记、范围前缀不在上表内的
会报 `!`（警告级，不阻塞开工）。已推送的历史不动。
